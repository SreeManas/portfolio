# Product Direction

This project is the digital identity of an engineer. It is not a resume,
portfolio, startup landing page, dashboard, or AI-themed showcase.

The north star is simple:

> Show how this engineer thinks.

Visitors should leave remembering clarity, restraint, craftsmanship, systems
thinking, attention to detail, and quality of decisions.

## Design Values

- Purpose over decoration
- Typography over graphics
- Whitespace over effects
- Story over lists
- Evidence over claims
- Calm over excitement
- Precision over spectacle
- Timelessness over trends

## Product Shape

The site is a single-page digital engineering journal with this narrative:

1. Hero
2. Current Mission
3. Featured Project
4. Engineering Thinking
5. Selected Work
6. Engineering Journal
7. Journey
8. Curiosity
9. Manifesto
10. Contact

This structure should only change if the alternative improves clarity and
strengthens the story.

## Experience Principles

- Every section must answer one clear question.
- The primary experience is light mode with warm neutral surfaces, near-black
  text, muted borders, and one restrained accent.
- Typography carries hierarchy before color or layout decoration.
- Motion is almost invisible and exists only to guide, explain, reveal, or
  confirm.
- Desktop is the primary experience, but mobile must be recomposed rather than
  mechanically stacked.
- The Command Center is a useful keyboard-first navigation and search layer,
  inspired by Raycast but never styled as a fake terminal.

## What Must Not Appear

- Skill bars
- Progress circles
- Technology logo walls
- Glassmorphism
- Particle backgrounds
- Neural networks
- Floating icons
- Typing animations
- Auto-playing videos
- Random gradients
- Decorative AI imagery
- Fake terminal hero
- Buzzword-heavy copy
- Meaningless counters

## Engineering Standards

- React
- TypeScript
- TailwindCSS
- Framer Motion, used sparingly
- Reusable components
- Composable architecture
- Clean folder structure
- Accessibility-first implementation
- Minimal dependencies
- Lighthouse target of 95+ where practical

## Decision Framework

Before adding anything, ask:

- Why does this exist?
- Can it be removed?
- Does it improve clarity?
- Does it strengthen the story?
- Would this still feel timeless in ten years?

If the answer is weak, remove it.

## Response Standard

Implementation responses should cover:

1. Reasoning
2. Design decisions
3. Tradeoffs
4. Implementation
5. Potential improvements

The work should never become a generic portfolio template. It should remain one
cohesive product.
